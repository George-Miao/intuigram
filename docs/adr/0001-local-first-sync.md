# Local-first synchronization

Popgram opens from a Synchronized Cache, continuously applies Telegram updates, and automatically reconnects and reconciles after connection loss. Each Telegram update is normalized into Popgram-owned data, and that data and its synchronization cursor commit atomically before the resulting durable state is exposed to the TUI. User actions may appear optimistically with explicit saving, pending, or failed state; Draft changes persist locally before Popgram reports them saved, while their cloud synchronization remains debounced. Popgram does not expose manual refresh; an explicit Reconnect action appears only during Reconnect Cooldown. This adds synchronization and commit latency but prevents restart gaps and state that appears once and then vanishes.
