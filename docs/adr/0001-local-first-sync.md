# Local-first synchronization

Intuigram opens from a Synchronized Cache, continuously applies Telegram updates, and automatically reconnects and reconciles after connection loss or a detected update gap. Account and Channel cursors remain separate; a discontinuous `pts` or global sequence is never advanced silently. Each Telegram update is normalized into Intuigram-owned data, and that data and every affected synchronization cursor commit atomically before the resulting durable state is exposed to the TUI. User actions may appear optimistically with explicit saving, pending, or failed state; Draft changes persist locally before Intuigram reports them saved, while their cloud synchronization remains debounced. Intuigram does not expose manual refresh; an explicit Reconnect action appears only during Reconnect Cooldown. This adds synchronization and commit latency but prevents restart gaps and state that appears once and then vanishes.
