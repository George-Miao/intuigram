# Local-first synchronization

Intuigram opens from a Synchronized Cache. It continuously applies Telegram updates. It automatically reconnects and reconciles after a connection loss or a detected update gap. Account cursors and Channel cursors stay separate. Intuigram never silently advances a discontinuous `pts` or global sequence. Intuigram normalizes each Telegram update into Intuigram-owned data. Intuigram atomically commits this data and each affected synchronization cursor before it shows the durable state in the TUI. User actions can appear optimistically with an explicit saving, pending, or failed state. Intuigram saves Draft changes locally before it reports that they are saved. Cloud synchronization of Drafts stays debounced. Intuigram does not provide manual refresh. It shows an explicit Reconnect action only during Reconnect Cooldown. This design adds synchronization and commit latency. It prevents restart gaps and prevents state that appears one time and then disappears.
