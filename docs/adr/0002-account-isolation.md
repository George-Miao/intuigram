# Account isolation

Intuigram keeps `global.db` for cross-Account runtime records and one `<telegram-user-id>.db` for each Account. The global registry retains each Account's stable notification identity alongside its display and active state. An Account database contains its MTProto authorization and session state, synchronization cursors, Synchronized Cache, Drafts, Draft History, per-Chat and per-Thread Transcript anchors, search index, media metadata, and durable Outbox, allowing related state to commit transactionally. A new login uses `.pending.db` until authorization reveals the user ID, then closes and atomically renames it. Redownloadable media bytes remain outside SQLite under the OS cache directory keyed by Telegram user ID. This avoids surrogate identifiers, limits corruption and recovery scope, permits per-Account Local Lock and removal, and prevents one Account's writer load from blocking every other Account at the cost of migrating and managing multiple databases.
