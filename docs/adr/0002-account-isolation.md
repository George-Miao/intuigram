# Account isolation

Intuigram uses `global.db` for cross-Account runtime records. It uses one `<telegram-user-id>.db` for each Account. The global registry stores the stable notification identity, display state, and active state of each Account. An Account database stores its MTProto authorization, session state, synchronization cursors, Synchronized Cache, Drafts, Draft History, per-Chat and per-Thread Transcript anchors, search index, media metadata, and durable Outbox. This arrangement lets related state commit in one transaction. A new login uses `.pending.db` until authorization gives the user ID. Intuigram then closes the database and renames it atomically. Redownloadable media bytes stay outside SQLite. Intuigram stores these bytes in the OS cache directory and uses the Telegram user ID as the key. This design does not use surrogate identifiers. It limits the scope of corruption and recovery. It permits per-Account Local Lock and Account removal. It also prevents the writer load of one Account from blocking all other Accounts. The cost is the migration and management of multiple databases.
