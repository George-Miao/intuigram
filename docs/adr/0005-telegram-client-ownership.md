# Telegram client ownership

Intuigram does not use `grammers-client`, `grammers-mtsender`, or `grammers-session`. Their high-level model omits Telegram behavior Intuigram requires, their sender exposes no transport seam, and their built-in storage conflicts with a single mature SQLite stack. The reusable `compio-mtproto` crate owns completion-based connections, authentication-key negotiation, MTProto session mechanics, bounded request correlation, acknowledgements, retries, connection-failure classification, and passive updates behind a raw invocation interface. It reuses the mature low-level grammers TL, codec, and cryptographic crates; Intuigram does not rewrite Telegram cryptography. Its route layer owns SOCKS5 and HTTP CONNECT negotiation, MTProxy obfuscation and transport selection, bounded connection attempts, and ordered direct fallback. `intuigram-telegram` validates each candidate through MTProto key exchange and Telegram API initialization before accepting it, then owns login, data-center selection, raw requests, update normalization, and gap detection.

A live client is constructed inside a dedicated one-worker cluster using Compio's upstream actor API and never crosses back to the main thread. The actor retains a worker-local `LiveUpdates` driver so several correlated invocations and passive updates make progress together. Flood waits and cancellation belong to individual invocations; mailbox and invocation capacity are bounded. The actor's output contains only normalized adapter batches and explicit failure categories. An RPC-returned update is handed to the worker-local durability coordinator, which snapshots and drains the older buffered live-envelope prefix before publishing committed events and acknowledging the call. Later continuous traffic cannot extend that barrier or starve acknowledgement. A reserved cancellation signal can interrupt connection setup or a flood-waiting command without depending on mailbox capacity.

Account-owned media sessions are retained per data center and kept separate from ordinary control traffic. Cross-DC authorization is imported once per retained session, media-only endpoints are preferred when advertised, aligned file parts may be fetched concurrently under bounded byte and active-file admission, and ordered assembly happens outside the UI loop. Normalized file locations carry enough identity to select thumbnails without refetching Messages and can refresh expired file references. CDN redirects use Telegram's current CDN RSA keys with the same low-level grammers cryptographic primitives, then decrypt offset-aware AES-CTR parts, verify Telegram hashes, request reupload through the origin data center, and fall back when a CDN token is invalid. Reconnect coherently tears down or rebuilds the affected media sessions.

Native clipboard reads, attachment validation and byte reads, media capture, platform launching, media decoding, cache access, and download writes remain outside the Telegram actor; the actor receives owned upload bytes only after local preparation. Orderly shutdown awaits the actor and joins the cluster after durable updates have committed. This provides complete API coverage, thread isolation, and a coherent Compio runtime at the substantial cost of maintaining Telegram client behavior, actor lifecycle coordination, and protocol conformance.
