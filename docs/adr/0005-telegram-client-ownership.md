# Telegram client ownership

Popgram does not use `grammers-client`, `grammers-mtsender`, or `grammers-session`. Their high-level model omits Telegram behavior Popgram requires, their sender exposes no transport seam, and their built-in storage conflicts with a single mature SQLite stack. The reusable `compio-mtproto` crate owns completion-based connections, authentication-key negotiation, MTProto session mechanics, request correlation, acknowledgements, retries, reconnection, and data-center pools behind a raw invocation and update-stream interface. `popgram-telegram` owns login, update reconciliation, raw Telegram requests, and translation between current TL constructors and Popgram-owned data. Popgram initially retains mature low-level grammers TL generation, MTProto codec, and cryptographic crates rather than rewriting protocol schema generation or cryptography. The grammers sender implementation remains a useful reference for expected protocol behavior, state transitions, retry handling, and edge cases, but does not define Popgram's interface or runtime design. This provides complete API coverage and a coherent Compio runtime at the substantial cost of maintaining Telegram client behavior and protocol conformance.
