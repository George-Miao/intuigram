# Workspace crates

Intuigram is a virtual Cargo workspace whose packages all live under `crates/`. Intuigram-specific packages use the `intuigram-*` prefix, while genuinely reusable utilities use independent names. The initial crate seams are `intuigram` for composition and the executable, `intuigram-app` for application state and use-case interfaces, `intuigram-tui` for terminal interaction and presentation, `intuigram-telegram` for Telegram synchronization and protocol adaptation, `intuigram-store` for durable local records, `intuigram-media` for media transfer and cache policy, `intuigram-config` for layered configuration, `compio-mtproto` for reusable MTProto transport and raw invocation, `rich-clipboard` for platform clipboard content, and the dev-only `test-harness` for hermetic cross-layer behavior scenarios. `intuigram-app` solely owns canonical application state and its transitions. The TUI submits typed user intents and renders read-only view data; Telegram, storage, and media adapters submit typed events. Ratatui widgets, Telegram TL values, database rows, and other adapter-specific types never cross the `intuigram-app` interface. Dependencies point toward `intuigram-app`; the executable composes concrete adapters, and adapter crates do not depend on each other. `test-harness` may depend on production crates while `intuigram` includes it only as a dev-dependency; this test-only dependency cycle does not enter production builds. This creates independent test surfaces and reusable modules at the cost of more packages and explicit interfaces. New crates require a demonstrated seam and meaningful hidden behavior rather than merely grouping related types.
