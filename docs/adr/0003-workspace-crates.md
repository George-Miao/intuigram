# Workspace crates

Intuigram is a virtual Cargo workspace whose packages all live under `crates/`. Intuigram-specific packages use the `intuigram-*` prefix, while genuinely reusable utilities use independent names. The crate seams are `intuigram` for the executable entrypoint, colorful command hierarchy, and process argument parsing; `intuigram-app` for orchestration and concrete adapter composition; `intuigram-lib` for canonical application state and use-case interfaces; `intuigram-tui` for terminal interaction and presentation; `intuigram-telegram` for Telegram synchronization and protocol adaptation; `intuigram-store` for durable local records; `intuigram-media` for media transfer and cache policy; `intuigram-config` for layered configuration; `compio-mtproto` for reusable MTProto transport and raw invocation; `compio-term` for Compio-native terminal readiness; `rasterm` for reusable terminal raster detection, geometry, protocol encoding, external-renderer commands, and image lifecycle; `rich-clipboard` for platform clipboard content; and the dev-only `test-harness` for hermetic cross-layer behavior scenarios.

Typed actors come from Compio's upstream `actor` feature; Intuigram does not carry a second actor implementation in the workspace. `rasterm` owns no terminal UI or product model and accepts owned RGBA images plus cell placements rather than Ratatui or Intuigram values. `intuigram-lib` solely owns canonical application state and its transitions. The TUI submits typed user intents and renders read-only view data; Telegram, storage, and media adapters submit typed events. Ratatui widgets, Telegram TL values, database rows, actor mailboxes, and other adapter-specific types never cross the `intuigram-lib` interface.

Domain-facing dependencies point toward `intuigram-lib`; adapter crates do not depend on `intuigram-app`, and `intuigram-app` composes the adapters. The `intuigram` package depends on Compio and `intuigram-app` in production. It owns the `#[compio::main]` runtime entrypoint plus Clap-specific syntax and styling, translates parsed values into the framework-free validated `Global` flags struct and `Command` enum exported by `intuigram-app`, and awaits orchestration without exposing Clap below the process package. Cross-layer behavior scenarios belong to `intuigram` because it is the top-level process package; it uses `test-harness` as a development dependency, and the harness depends downward on `intuigram-app` plus the production state and adapter crates it exercises. Neither `intuigram-app` nor lower crates depend on `intuigram` or `test-harness`, including for tests, so the complete package graph remains acyclic. The orchestration modules live directly beneath `intuigram-app/src`; there is no redundant `application` wrapper. This creates independent test surfaces and reusable modules at the cost of more packages and explicit interfaces. New crates require a demonstrated seam and meaningful hidden behavior rather than merely grouping related types.
