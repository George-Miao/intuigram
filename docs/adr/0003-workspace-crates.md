# Workspace crates

Intuigram is a virtual Cargo workspace. All packages are under `crates/`. Intuigram-specific packages use the `intuigram-*` prefix. Reusable utilities use independent names. The crate seams are as follows: `intuigram` owns the executable entrypoint, colorful command hierarchy, and process argument parsing; `intuigram-app` owns orchestration and concrete adapter composition; `intuigram-lib` owns canonical application state and use-case interfaces; `intuigram-tui` owns terminal interaction and presentation; `intuigram-telegram` owns Telegram synchronization and protocol adaptation; `intuigram-store` owns durable local records; `intuigram-media` owns media transfer and cache policy; `intuigram-config` owns layered configuration; `compio-mtproto` owns reusable MTProto transport and raw invocation; `compio-term` owns Compio-native terminal readiness; `rasterm` owns reusable terminal raster detection, geometry, protocol encoding, external-renderer commands, and image lifecycle; `rich-clipboard` owns platform clipboard content; and the development-only `test-harness` owns hermetic cross-layer behavior scenarios.

Typed actors come from the upstream Compio `actor` feature. Intuigram does not include a second actor implementation in the workspace. `rasterm` does not own terminal UI types or product model types. It accepts owned RGBA images and cell placements instead of Ratatui or Intuigram values. Only `intuigram-lib` owns canonical application state and its transitions. The TUI sends typed user intents and renders read-only view data. Telegram, storage, and media adapters send typed events. Ratatui widgets, Telegram TL values, database rows, actor mailboxes, and other adapter-specific types never cross the `intuigram-lib` interface.

Domain-facing dependencies point to `intuigram-lib`. Adapter crates do not depend on `intuigram-app`. `intuigram-app` composes the adapters. The `intuigram` package depends on Compio and `intuigram-app` in production. It owns the `#[compio::main]` runtime entrypoint and the Clap-specific syntax and style. It converts parsed values into the framework-free validated `Global` flags struct and `Command` enum that `intuigram-app` exports. It waits for orchestration without exposing Clap below the process package. Cross-layer behavior scenarios belong to `intuigram` because it is the top-level process package. It uses `test-harness` as a development dependency. The harness depends on `intuigram-app` and on the production state and adapter crates that it tests. `intuigram-app` and lower crates do not depend on `intuigram` or `test-harness`, including in tests. Thus, the complete package graph stays acyclic. The orchestration modules are directly under `intuigram-app/src`. There is no redundant `application` wrapper. This design gives independent test surfaces and reusable modules. The cost is more packages and explicit interfaces. A new crate requires a demonstrated seam and meaningful hidden behavior. Do not create a crate only to group related types.
