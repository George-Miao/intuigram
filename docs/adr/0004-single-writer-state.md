# Single-writer state

One asynchronous `intuigram-app` task exclusively owns mutable application state and applies typed user intents and adapter events in a deterministic order. The TUI renders immutable view snapshots or deltas and continues accepting input while Telegram, storage, media, clipboard, and other I/O execute independently and return typed results through bounded channels. No adapter exposes shared mutable state or requires cross-crate locking. UI-to-adapter effect delivery never waits for queue capacity: saturation is surfaced as an error. Chat-history requests allow one in-flight load and coalesce further navigation to the latest pending Chat, so stale work cannot build an input-blocking queue. This makes update, optimistic-action, acknowledgement, selection, and Draft ordering testable through the `intuigram-app` interface at the cost of explicit event, backpressure, and shutdown design.
