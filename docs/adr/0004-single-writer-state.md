# Single-writer state

Only `intuigram-lib` owns mutable application state. It provides a synchronous reducer. The reducer applies one typed user intent or adapter event in a deterministic order. It returns an immutable view and not more than one adapter effect. The `intuigram` process package creates the main-thread Compio runtime through `#[compio::main]`. It parses a validated global-flags struct and command enum. It then waits for startup. After startup, the `intuigram-app` composition runtime owns the reducer, terminal input, rendering, result aggregation, and nonblocking platform effects. Hermetic behavior tests keep their synchronous driver private to `test-harness`. A dedicated one-worker Compio actor cluster owns each live Telegram Account session. Only typed commands, normalized results, media bytes, and normalized update batches cross this thread boundary.

The composition loop polls persistent sources, one retained durable-Outbox coordinator, and an explicitly bounded set of correlated effect futures in place. Telegram control, small media, large transfers, ordered local work, and independent local work have separate admission rules. Small and large media have limits for each data center. These limits use the live Telegram auto-download limits and conservative defaults. Visible previews and avatars have priority over background prefetch. The runtime cancels or coalesces superseded viewport work. A slow operation does not stop terminal input or independent work. Poll priority changes after each ready source. Thus, continuous Telegram updates, terminal input, backend completions, and animation frames cannot starve the other sources. Dirty state controls rendering. An idle runtime parks on registered wakers. Loading-animation timers start only when the view reports pending work.

Blocking SQLite work stays on dedicated database threads. Outbox admission and lifecycle transitions, Draft persistence, and selection persistence use typed `AccountStore` endpoints. These endpoints use a storage lane that is independent from Telegram control. Native clipboard work, attachment reads, media capture, launch work, media decoding, cache work, and download-write work stay outside the Telegram mailbox. No adapter exposes shared mutable application state or requires cross-crate locking. Effect admission never waits for capacity. Saturation produces an error. The runtime coalesces replaceable Draft and notification work before admission. Chat-history requests permit one in-flight load. The runtime coalesces more navigation into the latest pending Chat. Thus, stale foreground work cannot create a queue that blocks input. Root-Chat history warmup uses a fixed cursor to walk the known Chat directory. It does not add all Chats to the queue at one time. After each completion, the latest foreground request gets priority before the next background load starts. Each load requests one bounded recent page. It yields before it requests older history in increments.

Shutdown stops new interaction. It cancels Telegram calls through a reserved cross-thread signal. It drains accepted independent effects and each durable update commit that an RPC already produced. It then stops and joins the driver, actor, and cluster. Interrupted replay-safe sends return to the durable FIFO with their stable Telegram identity. Replay-unsafe mutations enter an explicit unknown-outcome state. This design makes reducer ordering testable through `intuigram-lib`. It makes composition ordering testable through `intuigram-app`. The cost is explicit polling, bounded cross-thread backpressure, and coordinated shutdown.
