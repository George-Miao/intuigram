# Single-writer state

`intuigram-lib` exclusively owns mutable application state and exposes a synchronous reducer that applies one typed user intent or adapter event in deterministic order, returning an immutable view and at most one adapter effect. The `intuigram-app` composition runtime owns that reducer, terminal input, rendering, result aggregation, and nonblocking platform effects; the `intuigram` executable only delegates startup to it. A dedicated one-worker Compio actor cluster owns each live Telegram session; only typed commands, normalized results, media bytes, and normalized update batches cross that thread boundary. The composition loop polls persistent sources, one retained durable-Outbox coordinator, and an explicitly bounded set of correlated effect futures in place, so waking for terminal input does not cancel an in-flight operation and one slow effect does not prevent independent work from starting. Poll priority rotates after every ready source so a sustained stream of Telegram updates, terminal input, backend completions, or animation frames cannot starve the other sources. Blocking SQLite work remains on dedicated database threads, and Outbox admission and lifecycle transitions, Draft persistence, and selection persistence use their typed `AccountStore` endpoints on a storage lane independent from the serial Telegram lane. Only the claimed Outbox operation's Telegram invocation crosses into the actor. Native clipboard, attachment reads, media capture, launch, media decoding, cache, and download-write work remains outside the Telegram mailbox. No adapter exposes shared mutable application state or requires cross-crate locking. Effect enqueueing never waits for capacity: saturation is surfaced as an error, while replaceable Draft and notification work is coalesced before admission. Chat-history requests allow one in-flight load and coalesce further navigation to the latest pending Chat, so stale foreground work cannot build an input-blocking queue. Root-Chat history warmup walks the known Chat directory through a fixed cursor rather than enqueueing every Chat; each completion gives the latest foreground request priority before continuing the next background load. Each load requests one bounded recent page and yields before older history is requested incrementally, so opening one large Chat cannot monopolize the backend. Shutdown stops new interaction, cancels Telegram calls through a reserved cross-thread signal, drains independent accepted effects and any durable update commit already produced by an RPC, then stops and joins the driver, actor, and cluster. Interrupted replay-safe sends return to the durable FIFO with their stable Telegram identity; replay-unsafe mutations become an explicit unknown outcome. This makes reducer ordering testable through the `intuigram-lib` interface and composition ordering testable through `intuigram-app`, at the cost of explicit polling, bounded cross-thread backpressure, and coordinated shutdown.
