# Single-writer state

`intuigram-lib` exclusively owns mutable application state and exposes a synchronous reducer that applies one typed user intent or adapter event in deterministic order, returning an immutable view and at most one adapter effect. The `intuigram` process package creates the main-thread Compio runtime through `#[compio::main]`, parses a validated global-flags struct plus command enum, and awaits startup. The `intuigram-app` composition runtime owns the reducer, terminal input, rendering, result aggregation, and nonblocking platform effects after startup; hermetic behavior tests keep their synchronous driver private to `test-harness`. A dedicated one-worker Compio actor cluster owns each live Telegram Account session; only typed commands, normalized results, media bytes, and normalized update batches cross that thread boundary.

The composition loop polls persistent sources, one retained durable-Outbox coordinator, and an explicitly bounded set of correlated effect futures in place. Telegram control, small media, large transfers, ordered local work, and independent local work have separate admission rules. Small and large media are bounded per data center by Telegram's live auto-download limits with conservative defaults. Visible previews and avatars precede background prefetch, superseded viewport work is cancelled or coalesced, and one slow operation does not prevent terminal input or independent work from progressing. Poll priority rotates after every ready source so sustained Telegram updates, terminal input, backend completions, or animation frames cannot starve the other sources. Rendering is dirty-state driven; an idle runtime parks on registered wakers, while loading animation timers are armed only when the view reports pending effort.

Blocking SQLite work remains on dedicated database threads. Outbox admission and lifecycle transitions, Draft persistence, and selection persistence use typed `AccountStore` endpoints on a storage lane independent from Telegram control. Native clipboard, attachment reads, media capture, launch, media decoding, cache, and download-write work remains outside the Telegram mailbox. No adapter exposes shared mutable application state or requires cross-crate locking. Effect enqueueing never waits for capacity: saturation is surfaced as an error, while replaceable Draft and notification work is coalesced before admission. Chat-history requests allow one in-flight load and coalesce further navigation to the latest pending Chat, so stale foreground work cannot build an input-blocking queue. Root-Chat history warmup walks the known Chat directory through a fixed cursor rather than enqueueing every Chat; each completion gives the latest foreground request priority before continuing the next background load. Each load requests one bounded recent page and yields before older history is requested incrementally.

Shutdown stops new interaction, cancels Telegram calls through a reserved cross-thread signal, drains independent accepted effects and any durable update commit already produced by an RPC, then stops and joins the driver, actor, and cluster. Interrupted replay-safe sends return to the durable FIFO with their stable Telegram identity; replay-unsafe mutations become an explicit unknown outcome. This makes reducer ordering testable through `intuigram-lib` and composition ordering testable through `intuigram-app`, at the cost of explicit polling, bounded cross-thread backpressure, and coordinated shutdown.
